# Прогрессия: как устроено

Файл начинался как ТЗ; всё описанное в нём сделано, поэтому здесь — нынешние правила и числа.
Референс — TerraTech: у GSO пять грейдов, XP дают миссии и убийства (продажа не даёт), трофеи
ставятся без лицензии — грейд гейтит только МАГАЗИН. Явного дерева в TerraTech нет, древо —
наша надстройка. Чего сознательно не берём: RNG-гейтов, двойного гейта «исследовал → ещё
скрафти», «активной фракции» с кулдауном.

## Данные (`G.gd`)

```gdscript
const FACTIONS := { "start": {"name": "Starter", "grades": 5, "xp_thresholds": [0, 100, 300, 700, 1500]} }
const BLOCK_META := { Block.CABIN: {"f": "start", "g": 1, "rp": 0}, ... }   # фракция / грейд / цена в ДИ
const TECH_PARENT := { Block.BLOCK: Block.CABIN, ... }                      # рёбра древа
var faction_xp := {"start": 0}
var research_points := 0        # ДИ — валюта древа
var researched: Array = []      # изученные блоки
var quests_done: Array = []
```

Персист — `user://progress.json` (деньги, инвентарь, XP, ДИ, изученное, закрытые квесты):
дебаунс после изменения + запись при паузе и выходе. Состояние МИРА (машины, свободные блоки,
правки рельефа) живёт отдельно, в `world_persist.gd` и `user://world_save.json`.

API: `add_faction_xp(f, n)` (при переходе порога — сигнал `grade_up`), `grade(f)`,
`is_block_shop_unlocked(bt)`, `research(bt)`.

## Старт игры

- Изучено (`START_RESEARCHED`): CABIN, BLOCK, **SMALL_WHEEL**, **SMALL_DRILL**, COLLECTOR, SUPPORT.
- Выдаётся (`STARTER_KIT`, он же выдаётся при возрождении): 2 × BLOCK, 4 × SMALL_WHEEL,
  SMALL_DRILL, GUN — блоки кружат вокруг машины и осыпаются рядом, игрок собирает сам.
  Один список на оба случая, чтобы «начало игры» и «после смерти» не разъезжались.

**Малое колесо и малый бур — НАЧАЛО веток древа, а не ответвление от полноразмерных.** Игрок
начинает игру именно с них, и открывать их вторым шагом было бы враньём про порядок. Обычные
WHEEL и DRILL — шаг ВВЕРХ от малых.

## Правила

- **XP** (`G.on_game_event`, зовётся из шины `Q.report`):
  - `enemy_killed`: +15 за машину;
  - `ore_mined`: +1;
  - квест: поле `reward_xp`;
  - `money_earned` XP НЕ даёт (как в оригинале).
- **ДИ**:
  - квест: поле `reward_rp`;
  - первое убийство нового ВИДА врага: +5 (видов пока один — задел);
  - **за каждую убитую машину — по её СТОИМОСТИ** (`G.rp_for_kill`): база `RP_KILL_BASE`
    вычитается (платим за то, чем машина отличается от «кабина плюс колёса»), дальше по
    `RP_KILL_STEP` за ступень, потолок `RP_KILL_MAX`. Стоимость меряется ОДИН РАЗ при
    рождении машины: считать при смерти значило бы платить за то, насколько аккуратно её
    разобрали.
- **Гейтинг — только магазин гаража.** Трофеи (дроп врагов, пылесос коллектора, чанки) ставятся
  всегда, без лицензии.
- **Древо**: нода доступна ⇔ родитель изучен ∧ `grade(f) >= g` ∧ `research_points >= rp`.
  Исследование списывает ДИ, добавляет блок в `researched`, кладёт **+1 экземпляр в инвентарь**
  и открывает его в магазине.

## Цены — следствие одной таблицы

Руками задаётся только `G.METAL_PRICE = [25, 35, 45, 60]` (Ferrite, Cuprite, Silicate,
Titanite). Дальше:

- руда = `ORE_FRACTION` (0.4) от своего слитка — переплавка идёт 1:1, поэтому пятикратной
  разницы быть не может;
- компонент = сумма рецепта × `CRAFT_MARKUP` (1.25);
- **блок в магазине = материалы × `SHOP_MARKUP` (1.3)** — `G.shop_price`;
- разбор в Scrapper = половина рецепта теми же материалами.

`SHOP_MARKUP` > 1 — ГЛАВНОЕ правило экономики: «продать материалы и купить блок» обязано быть
хуже, чем «собрать самому», иначе фабрикатор, компонентный завод и Scrapper не нужны. Ровно
это и было сломано: блок из материалов на 300$ стоил в магазине 5$, и правильной игрой было
продать всё сырьё. Отдельного списка цен в `tech_ui` больше нет — он бы разъехался с рецептами.

Якорь всей таблицы — ферритовая руда за 10$: на ней настроены задания «заработай N$», поэтому
её цену трогать нельзя, не пересчитав их.

## UI

- **Магазин** (`tech_ui.gd`): закрытый блок — серый слот с причиной («грейд N» / «исследуй в
  древе»), кнопка покупки выключена.
- **Полоска XP и грейда + счётчик ДИ** — шапка гаража.
- **Вкладка ДРЕВО**: ярусы по грейдам, у ноды четыре состояния (изучена / доступна / не хватает
  ДИ / закрыта грейдом), тап — превью с ценой и требованием, второй тап — «исследовать».
- **Grade-up**: реплика Механика + тост о том, что открылось.
